# 多皮肤校准档案实施计划

## 目标

在不降低识别阈值、不引入 OCR 依赖的前提下，使 Windows 10 同一模拟器中的
JJ 象棋与天天象棋各自保留校准，并在同步或开始分析时自动选择正确皮肤档案。

## 任务 1：用失败测试锁定持久化行为

- 在 `test_assistant.py` 添加两个不同模板档案并存、重载、去重测试。
- 添加单个档案损坏时仍加载其他健康档案的测试。
- 添加旧顶层 `config.json/samples.npz` 自动迁移为候选的测试。
- 先运行这些测试，确认它们因接口尚不存在而失败。

## 任务 2：用失败测试锁定自动选择行为

- 构造同采集源、同方向、同尺寸但字形不同的两套棋盘图像。
- 断言每个图像都选择自己的档案，而不是当前 `self.calibration`。
- 断言尺寸、采集源、方向不匹配的档案不会参与识别。
- 断言全部失败时返回最高置信度原始错误和“无匹配皮肤档案”提示。

## 任务 3：实现最小持久化函数

- 在 `app.py` 添加档案内容指纹函数。
- 添加 `save_calibration_profile`：保留顶层兼容副本并写内容寻址目录。
- 添加 `load_calibration_profiles`：加载档案目录、去重、容错，并回退旧顶层档案。
- 不改变 `Calibration.save/load` 文件格式，降低迁移风险。

## 任务 4：实现候选过滤和自动择优

- 添加候选过滤函数，按 `rotated/source_id/frame_shape` 做硬约束。
- 添加识别选择函数：合法优先，其次置信度；无候选时生成确定性错误。
- 保持现有 `Calibration.recognize` 的光圈屏蔽、占位、身份和合法性防线不变。

## 任务 5：接入应用生命周期

- 启动时加载所有档案，并保留最新档案作为 UI 默认方向。
- 每次成功校准将新档案加入集合而不覆盖其他皮肤。
- `sync_current_board` 每个重试帧都在全部适用档案中自动选择。
- `toggle` 未使用已同步局面时采用相同选择逻辑。
- 成功选择后更新 `self.calibration`，后续运动跟踪继续使用同一皮肤档案。

## 任务 6：回归与真实引擎验证

- 运行新增测试和识别相关测试。
- 运行完整 `test_assistant.py`。
- 运行 `py_compile`。
- 用本地 Pikafish 对标准局面和将军局面做真实 UCI 冒烟测试。
- 检查 `git diff`，只报告本次修改，不覆盖用户已有未提交文件和图片。
