# 象棋连续落子运动跟踪设计

## 问题

校准模板来自标准开局的固定位置。棋子移动后，目标位置的背景、网格线和光影改变，90点最近邻分类会把空位或其他棋子误认成马（`N`），随后被数量上限拦截。无效局面无法进入轮次状态机，所以界面停在旧提示。

## 设计

标准开局仍用现有模板完成一次身份确认。辅助开始后，以已知棋盘为真值，不再逐格重新猜棋子身份。每帧提取保留红黑颜色差异的90个交叉点特征，与最近一次已接受截图比较；从最强的最多6个变化格中枚举“当前行棋方的已知棋子 → 合法目标点”，只接受变化证据明显领先且唯一的合法着法，生成新棋盘。

同一候选局面必须连续出现两帧才接受。接受后更新参考截图和棋盘、切换行棋方；轮到用户时调用Pikafish。没有变化、动画中、候选不唯一或证据不足时保持原局面并等待，不猜测、不切换轮次。

## 边界

- 不增加神经网络、OCR、云服务或自动点击。
- 保留自动校准优先、手动拖框兜底。
- 仅支持从程序已确认的标准开局开始连续跟踪；中途启动或漏掉完整一回合需重新校准。
- 窗口尺寸、皮肤或截图源改变仍需重新校准。

## 验证

- 安静帧不产生着法。
- 红炮移动、黑马移动能连续推导。
- 捕获着法能推导。
- 全盘亮度轻微变化不产生假着法。
- 经过两帧稳定后，`run_loop` 恰好产生下一次引擎请求。
