# 象棋跨帧走法恢复与引擎窗口隐藏设计

## 问题

程序每 700 毫秒截图，并要求候选局面连续出现两帧才提交。若用户落子后对手在第二次稳定确认前回应，当前截图会同时包含两步变化。旧实现只提交当前行棋方的一步，却把包含两步的截图保存为参考帧，导致第二步永久丢失，内部局面与真实棋盘分叉。

Pikafish 通过 `subprocess.Popen` 启动时没有传 Windows 无窗口标志，因此即使主程序使用 PyInstaller `--windowed` 打包，子进程仍会显示黑色控制台。

## 设计

运动识别仍只检查最多 6 个最强变化交点和现有象棋合法性规则，但允许从当前局面枚举 1～2 个连续合法走法。候选序列按能够解释的变化交点数量和总变化分数排序；没有唯一领先序列时继续等待，不猜测。

`MotionTracker` 接受序列后，把参考截图和内部棋盘原子更新到序列末端，同时先返回第一步局面，其余局面进入一个短队列，在后续观察中逐步返回。这样现有 `TurnTracker` 仍然一次只消费一个合法走法，能够正确切换两次回合并在最终真实局面上请求 Pikafish。

检测到至少两个明显变化交点但无法选出唯一合法序列时，状态显示“检测到棋盘变化，正在重新同步”，不再误报为“等待你落子”。

Windows 启动 Pikafish 时传 `subprocess.CREATE_NO_WINDOW`；非 Windows 传 0，保留现有 stdin/stdout UCI 管道、超时和关闭逻辑。

## 边界

- 最多恢复连续两步，覆盖一次轮询跨过用户与对手各一步的实际故障。
- 不增加视觉模型、依赖、自动点击或任意中盘识别。
- 变化无法唯一解释时不提交局面。
- 不改变 `TurnTracker`、FEN、中文记谱和 Tkinter 队列协议。

## 验证

- 一张最终截图同时包含红马和黑马走法时，依次返回两个中间局面，不能丢失黑方一步。
- 单步、捕获、旋转棋盘、高亮消退等已有测试继续通过。
- Windows 分支启动 Pikafish 时包含 `CREATE_NO_WINDOW`。
- 完整单元测试和 Python 语法检查通过。
