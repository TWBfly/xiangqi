# 开局棋盘稳定对齐与校准兼容设计

日期：2026-07-22
目标平台：Windows 10、JJ 象棋窗口截图与 ADB 截图

## 目标

彻底消除截图尺寸和采集源未变化、但棋盘内容在窗口内平移后触发的“识别置信度过低”错误。修复必须校正棋盘坐标根因，不降低识别阈值，也不得把不可靠盘面交给 Pikafish。

## 现场证据

`analysis_snapshot.png` 是程序实际保存的 585×988 BGR 识别输入，画面为红方在下的标准开局。

- 在该快照上重新运行 `detect_board_rect()` 得到 `(42, 272, 494, 766)`。
- 使用这个矩形创建新校准后，不启用对齐和启用对齐都能完整恢复标准盘面，置信度约为 `1.00`。
- 保持图片尺寸不变，仅把内容沿两个坐标轴平移 8～16 像素，不对齐时置信度落入 `0.31～0.24`；现场错误 `0.29` 位于相同区间。
- 当前工作区尚未提交的 Hough 网格搜索可以修正部分方向，但在 `-16px/-16px` 平移时仍返回约 `0.33` 并判定无效。
- 对同一平移画面重新调用已有的 `detect_board_rect()`，再用检测结果识别，真实快照恢复到约 `0.92`，合成标准盘面恢复到约 `0.89`，二者都完整识别。
- 当前 108 个自动化测试全部通过，但没有覆盖“截图外形不变、客户区内容整体平移”的场景。

这些结果排除了截图本身无法识别、置信度阈值过高和 Pikafish 搜索异常。决定性变量是棋盘交叉点坐标。

## 调用链与故障边界

```text
AssistantApp.sync_current_board
→ capture/window_frame 或 adb_frame
→ Calibration.recognize
→ 90 个 grid_points 的模板特征与圆占用判断
→ recognition_confidence / validate_board
→ board_to_fen
→ AssistantApp.analyze_snapshot
→ PikafishEngine.get_best_move
→ UCI: position fen ... / go ...
```

识别无效时，`sync_current_board()` 在 `board_to_fen()` 之前返回，不创建分析线程。官方 Pikafish 的 `UCIEngine::position()` 收到 `position` 后才调用 `Engine::set_position()`，后者再调用严格校验 FEN 的 `Position::set()`。因此本次 `0.29` 产生于本地视觉层，不修改 `/xiangqi/pikafish`。

本地 Pikafish 源码提交 `7c09ec25` 比 2026-07-22 官方 `master` 落后 5 个提交；线上差异没有修改 `src/uci.cpp` 或 `src/engine.cpp`，`src/position.cpp` 的变化是走子脏数据结构重组，与 FEN 输入和本故障无关。

## 根因

校准保存的是相对于整张截图的固定棋盘矩形和 90 个采样点。程序只检查：

- 截图高宽是否相同；
- 采集源标识是否相同；
- 执棋方向是否相同。

Windows 窗口的非客户区、模拟器工具栏、边框、最大化状态或 DPI 客户区原点可以变化，同时保持整张截图高宽不变。此时固定采样点落到棋子边缘或相邻背景，模板分数同时下降。重复截取同一个静态偏移画面不会恢复，放宽全局置信度只会允许错误棋局通过。

当前 Hough 回退对所有检测圆与 90 个预测格点做匹配。棋盘外的圆形 UI、错误的透视斜率和多个近似平移会产生局部最优，因此它在不同平移方向上表现不对称。标准开局本身具有更强约束：上下两排各有 9 个等距棋子，现有 `detect_board_rect()` 已经利用了这个不变量，应优先复用。

另一个持久化风险是校准样本没有特征格式版本。当前工作区已修改 `_vector()` 的取样半径和向量长度；旧 `samples.npz` 仍可能被新代码加载，造成语义不兼容或矩阵维度错误。

## 方案比较

### 方案 A：强证据矩形优先、Hough 回退、校准格式版本化（采用）

启用网格对齐时，先调用已有 `detect_board_rect()`。检测矩形的宽高必须与原校准矩形接近，满足约束才用于本帧；检测失败或尺寸不符时，继续使用现有 Hough 平移搜索处理非标准中盘。

同时给保存的校准增加特征格式版本。缺少版本或版本不匹配的历史校准不再静默加载，用户只需在升级后重新校准一次。

优点：在产生分数之前修正坐标；复用现有检测器；不降低安全阈值；中盘仍保留当前回退能力；旧模板不会污染新特征算法。

### 方案 B：识别失败后自动覆盖校准

在同步失败时假设当前画面是标准开局，重新创建并保存校准。

它能覆盖开局，但会在同步动作中隐式改写持久配置；中盘失败时只能再次失败，且根因仍留在固定坐标路径。因此不采用。

### 方案 C：增加重试或放宽置信度

静态位移下每次重试看到的是相同错误坐标。放宽置信度可能让错误棋子身份通过结构校验并进入引擎。因此不采用。

## 详细设计

### 1. 棋盘矩形强证据优先

修改 `Calibration.recognize()` 现有 `align_grid` 分支：

1. 调用 `detect_board_rect(image)`。
2. 比较新旧棋盘宽度和高度；每个维度的差值不得超过半个校准格尺寸。
3. 满足约束时将结果作为本帧 `aligned_rect`，不修改持久化的 `self.rect`。
4. 检测失败或尺寸约束不满足时，运行现有 Hough 平移搜索。
5. 两种方法都无可靠证据时继续使用原矩形，让现有置信度和棋盘合法性校验安全失败。

尺寸约束只允许平移和轻微检测误差，不在识别阶段隐式接受缩放。真正改变模拟器分辨率或 DPI 后仍要求重新校准。

### 2. 置信度策略

不降低 `Calibration.threshold == 0.45`，不把重试次数当作修复。对齐发生在特征提取之前；只有正确坐标产生的模板分数才参与后续库存、占用和局面合法性判断。

保留当前工作区已有的识别安全检查，不借本次修复重写棋子分类器。

### 3. 校准格式版本

在 `config.json` 中保存明确的 `feature_version`。`Calibration.load()` 只接受当前版本；旧配置、缺失版本或不匹配版本返回清晰的“校准格式已升级，请重新校准”错误，由现有启动流程退回未校准状态。

这是一项一次性迁移：升级后的首次运行需要重新校准，后续启动继续复用新格式。未来只要 `_vector()`、网格语义或样本标签编码发生不兼容变化，就必须递增版本。

### 4. 应用版本与构建

更新 `APP_VERSION`，让 Windows 标题能够区分修复后的 EXE 与旧构建。继续使用现有 `build_exe.bat` 的目录式 PyInstaller 构建，不新增依赖。

## TDD 与验证

### 失败用例

1. 使用现有 `standard_board_image()` 创建校准。
2. 在保持画面尺寸不变的情况下把内容平移 `(-16, -16)`。
3. 调用启用对齐的 `recognize()`。
4. 当前代码应出现 RED：盘面无效；修复后必须恢复 `STANDARD_BOARD` 且置信度高于阈值。

第二个失败用例保存一份缺少 `feature_version` 的校准，当前代码会加载；修复后必须明确拒绝。

### 完整验证

- 定向运行新增测试并观察 RED → GREEN。
- 运行 `python3 -m unittest -v test_assistant.py`。
- 运行 `python3 -m py_compile app.py capture.py board_recognition.py pikafish_engine.py game_state.py`。
- 运行 `git diff --check`，并区分本次增量与工作区原有空白问题。
- 本地回放 `analysis_snapshot.png`：原图与正负方向平移都必须识别标准盘面。
- 验证红黑翻转、截图尺寸变化和错误棋盘仍被拒绝。
- Windows 10 重新执行 `build_exe.bat`，确认标题版本更新，并进行一次窗口截图现场同步。

## 验收标准

- 标准开局画面相对旧校准平移至少正负 16 像素时，程序仍能恢复完整标准盘面。
- 不降低识别阈值，不通过错误棋盘，不增加第三方依赖。
- 不兼容的旧校准不会被静默复用，提示用户完成一次重新校准。
- 识别失败时不生成 FEN、不启动 Pikafish。
- 自动化测试和语法编译通过。
- Windows 10 新构建能从标题版本上与旧 EXE 明确区分。

## 非目标

- 不支持在截图尺寸变化后自动缩放旧校准。
- 不替代手动拖框兜底。
- 不增加 OCR、神经网络、多帧投票或新的图像依赖。
- 不修改 Pikafish 搜索、NNUE 或 UCI 实现。
