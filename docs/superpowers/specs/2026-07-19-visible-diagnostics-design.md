# 可视化诊断截图设计

## 目标

让普通用户不需要理解 `%APPDATA%`、隐藏目录或文件路径，就能在象棋辅助器内直接看到最近一次识别恢复的前后画面。

## 用户体验

主界面增加“查看诊断”按钮。点击后打开独立预览窗口：

- 左侧显示“参考画面”，对应 `diagnostic_reference.png`。
- 右侧显示“当前画面”，对应 `diagnostic_current.png`。
- 每张图片下方显示文件名、生成时间和完整路径。
- 提供“打开诊断目录”按钮。
- 关闭预览窗口不影响后台识别和引擎。

如果图片尚未生成，预览窗口不报技术异常，而是显示：

```text
尚无诊断截图
连续三次无法把棋盘变化解释为合法走法后，程序会保存最近一组画面。
保存目录：<实际路径>
```

## 生成时机

当前实现只在全盘恢复失败时保存。本次改为：`MotionTracker` 连续三次无法解释变化并触发完整棋盘恢复时，无论完整识别成功还是失败，都保存：

- 恢复前最近一次已确认参考帧；
- 触发恢复的当前帧。

正常等待、单次选中光圈、第一帧候选和已经成功接受的走法不保存，避免无意义磁盘写入。

文件名固定为：

```text
diagnostic_reference.png
diagnostic_current.png
```

每次覆盖上一组，因此目录中最多保留两张诊断图。

## 架构

### `board_recognition.py`

成功触发完整恢复的 `Recognition` 使用明确原因 `recovery_succeeded`；失败继续使用 `recovery_failed`。两者都代表应保存诊断画面，但只有失败影响错误提示。

### `app.py`

复用现有 `save_diagnostic_frames()`：

- 当原因属于 `{"recovery_succeeded", "recovery_failed"}` 时保存最新一组。
- 保存失败只追加中文提示，不改变 `GameState`。

新增两个最小 UI 方法：

- `show_diagnostics()`：读取固定的两张图片并创建 Tkinter `Toplevel` 预览。
- `open_diagnostic_directory()`：在 Windows 使用 `os.startfile()` 打开实际配置目录；不支持 `os.startfile` 的开发环境显示完整路径，不启动额外跨平台依赖。

预览图使用现有 Pillow `Image.open()`、`thumbnail()` 和 `ImageTk.PhotoImage`。预览窗口持有图片对象引用，避免 Tkinter 图片被垃圾回收。

## 布局

主窗口高度按新增按钮小幅增加。“同步当前棋盘”和“查看诊断”并排放置，不增加额外主界面层级。

预览窗口使用固定最大预览尺寸，保持原图比例；原文件不缩放、不覆盖。窗口可关闭，预览过程只读。

## 错误处理

- 两张图都不存在：显示“尚无诊断截图”和实际目录。
- 只存在一张：缺失侧显示“图片不存在”，存在侧正常显示。
- 图片损坏或无法读取：对应侧显示具体中文错误，不影响另一张。
- 目录不存在：点击“打开诊断目录”时先创建目录。
- Windows 打开目录失败：显示错误和完整路径。
- macOS/Linux 开发环境：不调用平台外部命令，只显示路径。

## 测试

最小自动验证覆盖：

1. 完整恢复成功时也调用 `save_diagnostic_frames()`。
2. 完整恢复失败仍保存，且保留具体错误。
3. 固定文件名覆盖，目录最多两张诊断图。
4. 无图片时返回“尚无诊断截图”所需状态和实际路径。
5. 两张有效图片可读取并缩放为预览对象。
6. 单张缺失或损坏不会阻止另一张显示。
7. 打开目录前自动创建目录。
8. 现有64项测试、实时回合、自动执棋方和 Pikafish 测试继续通过。

Windows 人工验收必须使用重新构建的 EXE：制造连续三次无法解释的棋盘变化，点击“查看诊断”，确认左右画面、路径、时间和“打开诊断目录”均可用。

## 非目标

- 不建立诊断历史图库。
- 不保存每一帧或每一步棋。
- 不自动弹出预览打断对局。
- 不上传、联网或发送诊断截图。
- 不引入新的图像或 GUI 依赖。
