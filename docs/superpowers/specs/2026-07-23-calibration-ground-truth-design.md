# 校准真值与默认搜索时间修复设计

## 目标

禁止中盘截图污染棋子模板；让旧的潜在污染样本自动失效；把默认 Pikafish 搜索时间从 10 秒改为 20 秒。

## 根因

`Calibration.create()` 当前把输入截图的 90 个格点直接按照 `STANDARD_BOARD` 标注，然后用同一张截图和同一批模板调用 `recognize()` 自检。训练数据和验证数据完全相同，无法证明输入真的是标准开局。

现场 `analysis_snapshot.png` 在三个合理矩形下都被 `Calibration.create()` 接受，而检测出的占用结构明确不等于标准开局，`circle_occupancy=False`。这证明中盘校准可以生成语义错误但自检通过的 `samples.npz`。

错误框中 `(2,4)` 的候选 `k=0.39` 超过单格最低分仍被拒绝并不矛盾：库存分配最多允许一个黑将。如果污染模板让另一格先占用了 `k`，当前格会被降级到低分替代标签，最终身份安全门将其拒绝。

Pikafish 只接收 FEN。增加搜索时间只提高正确 FEN 下的搜索深度，不会修复截图分类。

## 方案比较

### 方案 A：独立占用真值门 + 样本版本失效（采用）

在提取模板前，用现有 `_occupied_cells()` 检测棋子占用位置，并要求它与旋转后的标准开局 32 个位置完全一致。不一致则抛出明确错误，`AssistantApp.calibrate()` 不会执行 `save()`。同时升级 `CALIBRATION_FEATURE_VERSION`，使旧样本必须在静止标准开局重新生成。

优点是复用现有检测能力、没有新依赖，并从数据入口消除污染。

### 方案 B：允许中盘增量校准

中盘没有可靠棋子真值，除非要求用户逐格标注。自动增量学习会把识别错误重新训练进去，形成反馈放大，拒绝采用。

### 方案 C：引入中文 OCR

OCR 仍需解决格点定位、红黑方、旋转、光圈和低分辨率艺术字体，并不能修复错误监督。新增模型和 Windows 打包成本高，当前无必要。

## 数据流

```text
静止标准开局截图
  → 棋盘矩形
  → Hough 独立检测 32 个标准占用位置
  → 通过后才按 STANDARD_BOARD 提取模板
  → 自检
  → 原子保存 config.json / samples.npz
```

任何占用缺失或多余都会报告坐标，并保留磁盘上的原校准文件。

## 兼容与恢复

- 校准版本从 `1` 升到 `2`，旧文件加载时报“校准格式已升级，请重新校准”。
- 用户必须回到静止标准开局，只校准一次。
- 按钮文案改为“标准开局校准”。
- 默认搜索时间改为 20 秒，允许范围仍为 1–60 秒。

## 验收标准

- 非标准占用结构在模板提取和保存前被拒绝。
- 标准开局仍可自动、手动校准并正确加载。
- 版本 1 样本不能加载。
- 默认搜索时间和 GUI 初始值均为 20 秒。
- 现有识别、将军应对、真实 Pikafish 和全量测试继续通过。
- 不修改依赖和嵌套 Pikafish。
